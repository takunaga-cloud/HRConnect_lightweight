1. サーバーレス再構成の全体アーキテクチャ

3. 主な変更点と実装内容

① バックエンド（FastAPI on AWS Lambda）

  • Mangumアダプターの導入: backend/app/main.py
    FastAPIアプリケーションをAWS Lambdaのイベントハンドラー（handler = Mangum(app, lifespan="off")）としてエクスポートし、サーバーレス実行を可能にしました。
  • DynamoDBセッション・クライアントの最適化: backend/app/db/dynamodb.py
    Lambda実行ロール（IAM Role）の認証情報を自動解決する安全なパラメータ生成ロジックを実装。ローカル環境（DynamoDB Local）と本番AWS環境を同一コードでシームレスに切り替えられるようにしました。
  • Lambda用コンテナイメージの作成: backend/Dockerfile.lambda
    AWS公式の public.ecr.aws/lambda/python:3.11 をベースにしたDockerイメージを新規作成。PandasやOpenPyXLなど大容量ライブラリのZip容量制限（250MB）を完全に回避しました。
  • DynamoDB初期化・シードスクリプトの追加: backend/scripts/init_dynamodb.py
    AWS上のDynamoDBテーブルをワンコマンドで初期化し、管理者・一般ユーザーアカウントを投入するスクリプトを作成しました。

② インフラコード（AWS CDK & AWS SAM 両対応）

  • AWS CDK (TypeScript): infra/lib/hrconnect-serverless-stack.ts, infra/bin/infra.ts
    DynamoDB（オンデマンド・シングルテーブル設計）、S3（30日失効ライフサイクル）、Cognito User Pool & Client、Lambdaコンテナ関数、API Gateway HTTP API (v2) を包括するCDKプロジェクトを新規構築しました。
  • AWS SAM テンプレート: template.yaml
    sam build & sam deploy でデプロイを完結させたいケースに対応するため、同等リソースを定義したSAMテンプレートも同梱しました。

③ フロントエンド（Next.js App Router）

  • AWS Amplify Hosting 設定: amplify.yml
    Next.jsのApp Router / SSR をAWSマネージド環境でサーバーレスに自動ビルド＆配信できるCI/CD設定ファイルを作成しました。

④ デプロイスクリプト & 環境設定テンプレート

  • デプロイスクリプトの更新: deploy.sh
    CDKによるサーバーレスデプロイを実行し、完了後に必要な環境変数をわかりやすくガイドするよう全面改修しました。
  • 本番環境変数テンプレートの更新: .env.production.template
    古いPostgreSQL/EC2用設定を全撤廃し、DynamoDB/Lambda/Cognito/S3用のテンプレートに刷新しました。
  • Docker Composeの注記・構成更新: docker-compose.prod.yml
    本番はサーバーレス推奨である旨を明記し、コンテナ内ステージング用途向けにDynamoDB設定へ更新しました。

4. デプロイ手順

パターンA: AWS CDK を使用してデプロイする場合（推奨）

1. デプロイスクリプトを実行して、CDKインフラデプロイとフロントエンドビルドを行います：

./deploy.sh

2. デプロイ完了後に出力された ApiEndpoint や CognitoUserPoolId などを確認し、DynamoDBに初期ユーザーデータを投入します：

cd backend
python3 -m scripts.init_dynamodb
パターンB: AWS SAM を使用してデプロイする場合

SAM CLIを使ってガイド付き対話モードで即座にビルド・デプロイできます：

# ビルドの実行
sam build

# デプロイの実行（対話式でパラメータ設定）
sam deploy --guided
パターンC: フロントエンドのホスティング（AWS Amplify Hosting）
  1. AWSマネジメントコンソールで AWS Amplify Hosting を開きます。
  2. GitHub等のリポジトリを接続すると、ルートにある amplify.yml が自動的に読み込まれます。
  3. 環境変数に NEXT_PUBLIC_BACKEND_URL（上記で作成された API Gateway のエンドポイントURL）を設定して保存・デプロイします。
  4. 数分で全世界CDN配信とオンデマンドSSRが有効化されたフロントエンドが公開されます。
